Stick It to the Stickmanのキー配置に関する質問は、たいてい二つの場所から来ます。はしごで混乱した新規プレイヤーか、二人目のプレイヤーにコントローラーを渡そうとしている協力プレイのホストです。答えは見た目よりシンプルです。デフォルト配置は小さく、プレイヤーがぶつかる入力の問題には既知のコミュニティ修正があるからです。ゲームの再インストールが必要なものはありません。

このStick It to the Stickmanキー配置リファレンスは、コミュニティwikiの操作ページを土台に、開発者の公式itch.ioページで基本を照合しています。それ以外、特に協力プレイの修正はコミュニティ経験として明記します。

操作ページには、移動がAとD、はしごとジャンプがW、体を下げるのがS、攻撃がスペースかZ、スローがXとあります。五つのキーでゲーム全体をまかなえるため、入力がおかしく感じるときに割り当て変更が本当の問題であることはまれです。

## デフォルトのキーボード配置

wikiの操作ページによると、Sは体を下げてはしごを降り、Wははしごを登ってジャンプ、AとDで移動、スペースかZで攻撃、Xはアップグレードで解放した後にスローを発動します。これが完全なデフォルト配置で、公式itch.ioの記載（矢印キーで移動、スペースで攻撃、Enterで入る、Xでスロー）とも一致します。

二つのページの小さな違いは注目に値します。wikiはWASDを、itch.ioページは矢印キーを説明しており、ゲームは好みに応じて両方の移動スタイルを受け付け、同時に機能します。キーボードとコントローラーの混在セットアップが多いのはそのためです。両ページは要点で一致しており、Stick It to the Stickmanキー配置の虎の巻を作る人には心強い話です。

wikiページは、一部の操作は特定のアップグレードの後でしか意味を持たないことも示唆しています。スローが解放ゲートの後ろにあるという、丁寧な言い方です。公式ページは同じ四つの基本操作にEnterを加えており、配置がデモ時代から安定していることを裏付けます。

| キー | 動作 |
| --- | --- |
| A／Dまたは矢印キー | 左右に移動 |
| Wまたは上矢印 | ジャンプとはしごを登る |
| Sまたは下矢印 | 体を下げ、はしごを降りる |
| スペースまたはZ | 攻撃 |

保存済みの完全なリファレンスは[コミュニティwikiの操作ページ](https://stick-it-to-the-stick-man.fandom.com/wiki/Controls)にあり、パッチで基本が変わった場合の再確認には公式itch.ioページが適しています。

## 各キーの実際の役割

移動は話の半分です。はしごキーが重要なのは、いくつかの部屋と近道が登攀に依存しているからで、Sを覚えないプレイヤーは単純な縦移動で詰まります。Wでのジャンプは最初は違和感がありますが、専用ジャンプキーを期待しなくなれば自然になります。スペースでの攻撃も同様です。

コミュニティ報告は実用的な注意を加えます。ゲームははしごで「タップ」と「長押し」を別物として読むので、タップせず方向を押し続けること。Sをタップするプレイヤーははしごの上端を通り過ぎますが、長押しなら毎回きれいに降りられます。

スペースかZで攻撃できるのは、両手に届く選択肢があるということで、一人がコントローラーでもう一人がキーボードという協力プレイで重要です。Enterはメニュー、ドア、そしてitch.ioページが挙げる操作プロンプトのためのインタラクションキーです。

| 入力 | 使う場面 |
| --- | --- |
| スペース／Z | 弱・強を問わずすべての攻撃 |
| Wまたは上 | 上の階への移動と脱出 |
| Sまたは下 | はしごを安全に降りる |
| Enter | メニュー、プロンプト、部屋への入室 |

## スローと解放ゲート

操作ページは、スローはアップグレードで解放した後にしか機能しないと記しています。序盤にXを押して何も起きないプレイヤーはキーが壊れていると思いがちですが、ゲートは入力ではなく進行です。

スレッドは、解放は一度買えば恒久的だと確認しています。修正方法はスローのアップグレードを買って、すぐXを試すこと。解放後もXが動かないなら、次のセクションで本当の原因である入力競合を扱います。

繰り返し登場するStick It to the Stickmanキー配置の質問に「スローはコントローラーで使えるか」があります。コミュニティ報告はイエスで、同じ解放にマップされ、違いはパッドのどのボタンかだけです。現在のパッド割り当ては入力設定画面で確認できます。

| 状況 | たいていの意味 |
| --- | --- |
| 序盤にXが効かない | スローがまだ未解放 |
| Xが効いたり止まったり | 入力競合か割り当て変更を確認 |
| はしごキーが鈍い | タップせずSかWを押し続ける |
| 攻撃キーが遅れる | スペースとZを試し、きれいな方を使う |

## 割り当て変更と協力プレイの入力設定

割り当て変更はゲームのオプションにあり、触る理由として最も多いのは協力プレイです。古いビルドはキーボードしかプレイヤー1として認識しなかったため、ホストは二人目にコントローラーを渡す回避策を使っていました。

保存済みスレッドの修正は、一人目のプレイヤーが参加した後にコントローラーを抜き差しし、ゲームに二台目のデバイスとして認識させるというものでした。コミュニティ報告によると、後のアップデートでプレイヤーごとの正式なデバイス割り当てが追加されたので、まず入力設定を確認し、再接続トリックは古いビルド専用にしてください。

ソロプレイヤーにとって割り当て変更の効果は小さいですが、Stick It to the Stickmanキー配置のどのスレッドでも目立つコミュニティのコツがあります。Zで攻撃するならWをジャンプのままでも問題なく動き、Enterをカスタムバインドから外しておくとメニューの妙な挙動を避けられます。報告される割り当て問題の大半は、一つのキーに二つの動作を割り当てたことに由来します。

| 協力プレイの問題 | コミュニティの修正 |
| --- | --- |
| コントローラーがプレイヤー1扱い | 設定でデバイスを再割り当て |
| 二台目が見えない | 参加後に抜き差しする |
| キーボード二台が離れている | SteamリモートプレイかParsecを使う |
| 古いコントローラーが不安定 | 新しいパッドに替える。古いのは不安定と報告あり |

## ランの前に入力をテストする

真剣なランの前の2分間の入力チェックが多くの混乱を防ぎます。コミュニティプレイヤーは一階ではしごキー、攻撃キー、Xを試し、違和感があればリセットします。検証済みのStick It to the Stickmanキー配置は、練習したことのない凝ったカスタム配置より価値があります。

| チェック | 期待される結果 |
| --- | --- |
| はしごを降りる | S長押しで滑らかに降下 |
| ジャンプ | Wで上の階へ |
| 攻撃 | スペースもZも振れる |
| スロー | アップグレード購入済みならXが効く |

## FAQ

### Stick It to the Stickmanのキーボード配置は？

AとDで移動、Wではしごとジャンプ、Sで体を下げ、スペースかZで攻撃、Enterでインタラクト、Xはアップグレード解放後にスローを発動します。

### スローが効かないのはなぜ？

操作ページは、スローはアップグレードで解放した後にしか機能しないと記しています。キーが壊れていると決めつける前に、まずアップグレードを買ってXを再テストしてください。それでも失敗するなら割り当ての競合を確認しましょう。

### 二人目のプレイヤーにコントローラーを渡すには？

現在のビルドでは設定のデバイス割り当てを使い、古いビルドではコミュニティの再接続トリック（まずキーボードで参加し、その後コントローラーを抜き差し）を使います。トリックは主に古いビルド向けです。

### 離れた場所の二人がキーボードで遊べる？

はい。保存済みスレッドはSteamリモートプレイかParsecを推奨し、ホストはShift＋TabオーバーレイまたはParsecクライアントで友人を招待します。どちらも安定した接続が必要で、ホストは先にオーバーレイをテストすべきです。
